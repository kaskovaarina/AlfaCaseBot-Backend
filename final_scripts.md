# Пользовательские сценарии проекта AlfaCaseBot

## Сценарий 1: Регистрация нового пользователя
**Актор:** Новый пользователь. **Цель:** Создать аккаунт в системе.
**Основной поток:**
1. Пользователь нажимает «Нет аккаунта? Зарегистрироваться».
2. Вводит имя, email и пароль, нажимает «Создать аккаунт».
3. Система выполняет клиентскую валидацию и отправляет данные на сервер.
4. Сервер хеширует пароль (bcrypt), создает запись в БД и возвращает JWT-токены.
5. Система сохраняет токены и перенаправляет пользователя на главный экран.

## Сценарий 2: Вход в систему
**Актор:** Зарегистрированный пользователь. **Цель:** Авторизоваться.
**Основной поток:**
1. Пользователь вводит email и пароль, нажимает «Войти».
2. Сервер проверяет хеш пароля и возвращает JWT-токены.
3. Система сохраняет токены и открывает главный экран.

## Сценарий 3: Просмотр каталога кейсов
**Актор:** Авторизованный пользователь. **Цель:** Выбрать кейс.
**Основной поток:**
1. Пользователь нажимает иконку «Кейсы» в нижней панели.
2. Система загружает и отображает список кейсов в виде карточек.
3. Пользователь нажимает на карточку, система открывает экран с полным условием.

## Сценарий 4: Решение кейса и получение оценки от ИИ
**Актор:** Авторизованный пользователь. **Цель:** Отправить решение и получить обратную связь.
**Основной поток:**
1. Пользователь нажимает «Начать решение» и вводит текст (50–2000 слов).
2. Система выполняет клиентскую валидацию и отправляет решение на сервер.
3. Сервер выполняет многоуровневую проверку: формальные критерии → LinearSVM → сравнение с эталоном → 5 Ridge-моделей → GigaChat.
4. Система отображает экран результата с итоговой оценкой, очками, оценками по 5 критериям и текстовым фидбеком.

## Сценарий 5: Просмотр эталонного решения
**Актор:** Пользователь, получивший оценку. **Цель:** Изучить эталон.
**Основной поток:**
1. На экране результата пользователь нажимает «Посмотреть эталонное решение».
2. Система показывает диалог с предупреждением о блокировке повторной отправки.
3. Пользователь подтверждает, система загружает и отображает эталон с Markdown-форматированием.
4. Повторная отправка решения этого кейса блокируется.

## Сценарий 6: Оценка кейса пользователем
**Актор:** Пользователь, получивший оценку. **Цель:** Оценить качество кейса.
**Основной поток:**
1. Система предлагает оценить кейс (диалоговое окно).
2. Пользователь выбирает от 1 до 5 звёзд.
3. Система отправляет оценку на сервер и показывает сообщение «Спасибо за оценку!».

## Сценарий 7: Просмотр рейтинга
**Актор:** Авторизованный пользователь. **Цель:** Сравнить прогресс с другими.
**Основной поток:**
1. Пользователь нажимает иконку «Рейтинг».
2. Система загружает и отображает топ-5 пользователей с их именами и количеством очков.

## Сценарий 8: Просмотр профиля и выход из аккаунта
**Актор:** Авторизованный пользователь. **Цель:** Посмотреть статистику или выйти.
**Основной поток:**
1. Пользователь нажимает иконку «Профиль».
2. Система отображает уровень пользователя, имя, email, количество решенных кейсов и средний балл.
3. (Опционально) Пользователь нажимает «Выйти из аккаунта», система удаляет токены и возвращает на экран входа.
